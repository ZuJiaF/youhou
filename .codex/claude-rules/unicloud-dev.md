# uniCloud 开发规则

## 核心概念区分

### 云对象 vs 云函数
- **云对象**：包含多个方法的对象，每个方法可以被调用（这些方法也叫函数，但不是"云函数"）
- **云函数**：独立的函数文件，直接被调用

例如：
```js
// 云对象 user-center（包含多个方法）
module.exports = {
  async login() { ... },      // 方法
  async logout() { ... },     // 方法
  async getInfo() { ... }     // 方法
}

// 云函数 send-sms（独立函数）
exports.main = async (event, context) => {
  // ...
}
```

## 错误排查优先级

当云对象或云函数调用出错时，**第一优先级检查**：

### ⚠️ 是否已 URL 化

**问题表现**：
- 调用失败
- 404 错误
- 连接超时
- 无法访问

**排查步骤**：
1. 提醒用户：「云对象/云函数可能未 URL 化，请检查 uniCloud 后台」
2. 指引用户操作：
   - 登录 uniCloud Web 控制台
   - 进入对应服务空间
   - 找到云函数/云对象列表
   - 找到对应的云对象/云函数
   - 点击「详情」→「URL 化」
   - 启用 URL 化并保存

**何时需要 URL 化**：
- 需要通过 HTTP 请求直接访问
- 前端通过 `uniCloud.callFunction()` 或 `uniCloud.importObject()` 调用时不需要
- 第三方回调（如支付回调、消息推送）需要 URL 化

## 开发规范

### 1. 命名约定
- 云对象：使用中划线命名（如 `user-center`）
- 云函数：使用中划线命名（如 `send-sms`）
- 云对象方法：使用驼峰命名（如 `getUserInfo`）

### 2. 错误处理
优先考虑是否已 URL 化，然后再检查：
- 代码逻辑错误
- 参数校验问题
- 数据库连接问题
- 权限配置问题

### 3. 术语准确性
在沟通时注意：
- 「云对象的方法」≠「云函数」
- 「云对象中的函数」指的是方法
- 避免混淆概念导致理解偏差

## AI 助手工作规范

1. **排查错误时**：第一句话提醒检查 URL 化
2. **写文档时**：明确区分云对象和云函数
3. **讨论代码时**：使用准确术语（方法 vs 云函数）
4. **给建议时**：根据使用场景判断是否需要 URL 化
