# 输出表达规范

## 核心原则

**列出任何技术名词时，必须紧跟中文功能说明，不能只写英文名让用户自己猜。**

用户需要快速理解代码的业务含义，而不是停下来解读英文命名。

## 适用范围

以下内容必须附带中文说明：
- 方法名
- 文件路径
- 类名/组件名
- 云对象/云函数名
- 数据库集合名
- 字段名
- 变量名
- 配置项名

## 格式规范

### 1. 方法名
```
格式：`methodName`（方法功能说明）
示例：`recalcAllAvgDailySales`（重算所有商品的日均销量）
```

### 2. 文件路径
```
格式：`路径` — 文件说明
示例：`competitor/index.obj.js` — 竞对云对象，新增日均销量预计算逻辑
```

### 3. 字段名
```
格式：`fieldName`（字段含义）
示例：`avg_daily_sales`（日均销量）
```

### 4. 列表说明
当列出多个技术名词时：
```markdown
修改了以下方法：
- `getUserInfo`（获取用户信息）
- `updateUserProfile`（更新用户资料）
- `deleteAccount`（删除账户）
```

### 5. 文件清单
```markdown
需要修改的文件：
- `src/api/user.js` — 用户接口模块
- `src/views/profile.vue` — 个人资料页面
- `src/store/user.js` — 用户状态管理
```

## 验证步骤说明

验证步骤也要说人话，不要只写"调用哪个方法"，要写清楚**这步在验证什么业务目标**。

❌ **错误示例**：
```
测试步骤：
1. 调用 getUserList
2. 检查 response.data
3. 调用 updateUser
```

✅ **正确示例**：
```
测试步骤：
1. 获取用户列表，确认返回的列表包含所有活跃用户
2. 修改某个用户的昵称，确认修改成功
3. 重新获取列表，确认昵称已更新
```

## 代码注释中的应用

在代码中添加注释时，也要遵循此规范：

```javascript
// ❌ 错误：只写英文
const result = await getOrderList()

// ✅ 正确：附带业务说明
const orderList = await getOrderList() // 获取当前用户的所有订单
```

## 例外情况

以下情况可以省略中文说明：
- 极其常见的术语（如 `id`、`name`、`index`）
- 用户明确知道上下文时（例如正在讨论某个具体方法，后续提到时可简写）
- 代码示例中的临时变量

## AI 助手工作规范

1. **列出技术名词时**：立即附上中文说明
2. **写文档时**：首次出现的名词必须说明，后续可简写
3. **回复用户时**：假设用户不熟悉代码，主动解释业务含义
4. **列清单时**：每一项都要有功能说明
