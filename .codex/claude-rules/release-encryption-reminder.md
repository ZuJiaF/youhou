# 发行加密提醒规范

## 触发词：用户说"发行"时做什么

**"发行 / 发版 / 发布 / 出正式版 / 加密一份" = 执行项目的混淆/加密命令，生成加密产物。**

**不是** git commit、不是 git push、不是打 tag、不是 GitHub Release。

| 用户说 | 应该做 | 不要做 |
|---|---|---|
| 发行 / 发版 / 发布 | 跑项目 CLAUDE.md 里的加密命令，产出加密文件 | git commit / push / tag |
| 提交 / commit / 提交代码 | git commit | 跑加密 |
| 推上去 / push | git push | 跑加密 |
| 发行并提交 | 先加密，再 commit（源码+产物） | — |

判断依据：这类项目（油猴脚本、插件、商业软件）的"发行"指的是**交付给终端用户的加密产物**，代码仓库操作是另一回事。两者都要做时用户会明确说。

不确定时**先跑加密**（可重复生成、无副作用），并在回复里问一句是否还要提交。不要反过来先提交。

## 核心原则

**当修改需要发布加密版本的代码后，必须主动提醒用户是否需要生成发行版本。**

适用于：
- 油猴脚本（UserScript）
- 浏览器插件
- 商业软件
- 需要代码混淆/加密的项目

## 提醒时机

在以下情况修改代码后提醒：
- ✅ 修改功能代码
- ✅ 修复 Bug
- ✅ 调整配置或参数
- ✅ 更新版本号
- ❌ 仅讨论、未实际修改代码时不提醒

## 提醒格式

### 标准提醒

修改代码后，在回复末尾附上：

```
如果需要发行请告诉我，我将调用脚本生成一份加密过的文件，以便供用户使用。
```

### 用户确认后执行

根据项目的加密脚本执行相应命令。

## 项目特定配置

不同项目的加密方式不同，在项目的 CLAUDE.md 中指定：

### 示例 1：Node.js 加密脚本

```bash
node encrypt.js "<脚本文件路径>"
```

输出：`正式版-<原文件名>`

### 示例 2：Python 混淆工具

```bash
python obfuscate.py --input <源文件> --output <输出文件>
```

### 示例 3：Webpack/Rollup 构建

```bash
npm run build:prod
```

输出到 `dist/` 目录

### 示例 4：浏览器插件打包

```bash
npm run build
cd dist && zip -r ../extension-v1.0.0.zip .
```

## 工作流程

1. **修改代码并保存**
2. **更新版本号**（如果项目有版本号管理）
3. **在回复末尾添加加密提醒**
4. **用户确认需要加密**（或用户直接说"发行"）
5. **执行加密前先确认源码里的版本号已是本次新版本** —— 产物的版本号是从源码头部复制的，版本号没更新就发行，等于发了个旧版号的包，油猴/ScriptCat 不会提示用户更新
6. **执行项目指定的加密/构建命令**
7. **校验产物**：版本号正确 + 语法可解析（如 `node --check`）
8. **告知用户输出文件位置**

## 示例对话

### 对话示例 1：油猴脚本

```
用户：修复一下这个 bug
AI：已修复 Bug，版本号已更新为 1.2.4。

如果需要发行请告诉我，我将调用脚本生成一份加密过的文件，以便供用户使用。

用户：需要加密
AI：[执行] node encrypt.js "scripts/my-script.user.js"
加密文件已生成：scripts/正式版-my-script.user.js
```

### 对话示例 2：浏览器插件

```
用户：新增一个快捷键功能
AI：已新增快捷键功能，版本号已更新为 2.1.0。

如果需要发行请告诉我，我将生成生产构建版本。

用户：生成发行版
AI：[执行] npm run build
生产构建已完成，输出目录：dist/
```

## AI 助手工作规范

1. **修改代码后必须提醒发行/加密**
2. **提醒放在回复末尾，确保用户看到**
3. **等待用户明确确认后再执行加密**
4. **执行后告知输出文件位置和名称**
5. **如果加密失败，提示用户检查加密脚本**

## 注意事项

- 加密/混淆脚本由项目维护，不是 AI 自动生成
- 确保加密命令在项目文档中有明确说明
- 加密产物是否入库看项目习惯：有的项目把 `正式版-*` 一起提交（方便分发），有的不提交。跟随该项目 git 历史里的既有做法，不要自己改规矩
- 保留未加密的源代码用于后续开发
- 混淆产物体积大、内容不可读，**不要把产物内容打印到终端**（`cat`/`head` 整个文件），只看头部版本号和校验结果
