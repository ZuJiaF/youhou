# 手机接力 / 手机互联 自动接管

## ⚠️ 触发词优先匹配（最高优先级）

**只要用户消息中出现下列任一关键词/近义表达，立即跳到「工作流程」执行，不要按字面意思去解读，也不要反问：**

- 「接力」「启动接力」「开始接力」「要接力」「需要接力」
- 「手机接力」「手机互联」「手机编程」「手机对话」「手机接管」「手机接龙」
- 「让手机接」「手机能不能接」「手机也能看/也能操作这个对话」
- 「同步到手机」「把这个会话推到手机」「手机端围观」

### 常见误判（绝对避免）

❌ 把"这个对话需要手机可以接力" → 解读成"跨设备恢复上下文"，然后说"Claude Code 没有官方跨设备功能"  
❌ 反问"你说的接力是什么意思"  
❌ 建议用户手动复制上下文到手机端新会话  

✅ 正确反应：**立即执行下方工作流程，启动 `remote-bridge.js`**，一句多余的解读都不要有。

## 核心原则

**当用户在对话里表达「接力」「启动接力」「手机互联」「手机编程」「手机对话」「让手机接龙/接管」等意图时，说明用户想用手机 App 围观并接力当前电脑上的 Claude Code 会话。此时 AI 应：**

1. **搜本机**是否存在「AI 编程远程控制方案」项目（下称"方案项目"）
2. 找到后**读该项目的规则**（`CLAUDE.md`），理解最新的接力机制和注意事项
3. **直接在当前项目路径**（当前 Claude 的工作目录）启动桥接脚本 `remote-bridge.js`（手机接力桥接脚本）

## 解决的痛点

方案项目原本的用法是：**先**在方案项目路径下打开 Claude，**再**把真正的项目路径发给它去接力——两步流程。

本规则的目的：**省掉第一步**。既然用户已经在真正的项目里打开了 Claude，当前工作目录就是要接力的目标目录，桥接脚本会用「启动时的工作目录」自动推算会话记录目录，无需再手动传路径。用户直接在真正项目里说一句"接力"即可。

## 工作流程

### 1. 定位方案项目

先按默认位置查找，找不到再搜索本机常见目录：

```bash
# 默认位置（当前这台电脑）
C:\Users\fjh\Desktop\ai编程远程控制方案\remote-bridge.js
```

若默认位置不存在（比如换了电脑），用搜索定位标志文件 `remote-bridge.js`（桥接脚本）或目录名 `ai编程远程控制方案`：

```bash
# 在常见根目录下搜目录名
Get-ChildItem -Path C:\Users\$env:USERNAME\Desktop, C:\Users\$env:USERNAME\Documents `
  -Recurse -Directory -Filter "ai编程远程控制方案" -ErrorAction SilentlyContinue | Select-Object -First 1 -ExpandProperty FullName
```

- **找到** → 记下 `remote-bridge.js` 的完整路径，进入下一步
- **没找到** → 告诉用户"本机未发现 AI 编程远程控制方案项目，无法自动接力，请确认项目是否已克隆/存在"，不要伪造流程

### 2. 读方案项目的规则

找到方案项目后，**读它的 `CLAUDE.md`**（方案项目根目录），以那里的最新说明为准（接力含义、启动命令、坑点、云对象/手机端结构可能随项目演进而变）。本规则只负责"识别意图 + 定位项目 + 触发"，**具体怎么跑以方案项目 CLAUDE.md 为准**。

### 3. 在当前项目路径启动桥接脚本

**关键：不要 `cd` 到别处，就在当前工作目录启动**，这样脚本才会接力用户当前所在的真正项目：

```bash
# 当前工作目录 = 要接力的项目目录，直接启动
node "<方案项目路径>\remote-bridge.js"
```

脚本会用启动时的工作目录自动推算会话目录（把路径里非字母数字字符换成 `-`），把当前活跃会话推到云端，手机即可围观 + 发指令接力。

## 启动前必须提醒用户的坑

（以方案项目 CLAUDE.md 的最新说明为准，通常包括：）

1. **进程生命周期**：桥接脚本默认「启动即独立保活」——`node remote-bridge.js` 会自动 spawn 一个脱离进程树的独立进程，前台秒退，关掉终端/对话不影响接力。日志写到工作目录的 `bridge.log`。若要在前台看实时日志调试，加参数 `--attached`（或设 `BRIDGE_MODE=attached`）走旧的附属模式，此时脚本会随启动它的终端/对话被杀掉。
2. **同会话并发**：脚本运行时若电脑端交互式对话还开着，手机又同时发指令，两个 claude 进程会写同一会话文件导致上下文错乱。测试时提醒用户别同时在电脑端打字。
3. **电脑不能休眠**：接力期间电脑必须开机且不休眠，否则脚本停摆。

## AI 助手工作规范

1. **识别意图即行动**：听到"接力/手机互联/手机编程/手机对话/手机接管"，先搜方案项目，而不是反问"你说的接力是什么"
2. **不写死路径依赖**：默认路径找不到就搜索定位，兼容不同电脑
3. **在当前目录启动**：绝不 `cd` 到方案项目再启动，否则会接力错项目
4. **以方案项目规则为准**：读到方案项目 `CLAUDE.md` 后，按其最新说明执行，本规则不覆盖它
5. **启动后告知默认已独立保活**：关掉对话/终端不影响接力；要在前台看日志用 `--attached`；停止接力用手机点「停止接力」或 `taskkill`

## 例外情况

- 用户明确说"不是接力，是别的意思"（如聊天里提到"接力赛"）→ 不触发
- 本机确实没有方案项目 → 如实告知，不伪造流程
