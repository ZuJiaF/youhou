# 复杂文档意图 → 强制走 write-doc 技能

## 为什么需要这条规则

`write-doc`（写复杂任务文档技能）是一个 **skill**，只会被列进技能清单，需要 AI **主动识别意图**才会调用。实际使用中（尤其是手机桥接、口语化指令场景）经常出现："用户说做个复杂项目文档，AI 却直接手写文档 / 建了个普通目录，没触发技能"。

规则是每次会话都注入上下文的强约束。用这条规则做「意图路由」，把"被动等 AI 想起技能"变成"每次都强制提醒去用技能"，提升触发率。

## 核心原则

**当用户表达"写复杂文档 / 规划文档 / 大型功能开发文档 / 多角色协作文档"等意图时，第一反应必须是调用 `write-doc` 技能（Skill 工具），而不是直接用 Bash 建目录、直接手写 Markdown 文档。**

## 触发信号（命中任一即应走 write-doc）

- "做个复杂项目文档" / "做个复杂任务文档"
- "写个规划文档" / "写个方案文档" / "写个设计文档"（针对一个较大功能/项目）
- "建个文档目录整理一下这个功能怎么做"
- "帮我把这个大功能的需求、设计、开发计划整理成文档"
- 任何"需要多轮协作、需求→设计→开发→验收"性质的大型文档需求

## 正确做法

1. 识别到上述意图 → **先调用 `write-doc` 技能**（不要先急着建目录/写文件）
2. 按技能流程：确认文档名 → 加 `YYMMDD-` 日期前缀 → 在 `复杂任务交互文档/` 目录创建 → 顶部自动写入四角色定义模板（需求询问者 / 文件探索先锋 / 执行者 / 验收者）
3. 具体格式与角色定义**以 write-doc 技能的 SKILL.md 为准**，本规则只负责"把意图导向技能"

## 反面案例（不要这样做）

❌ 用户说"做个复杂项目文档" → AI 直接 `mkdir 复杂项目文档目录` + 手写 6 个主题 md 文件（漏掉了四角色协作模板、目录名和文件名也不符合技能规范）

✅ 用户说"做个复杂项目文档" → AI 调用 `write-doc` 技能 → 生成带角色定义的 `复杂任务交互文档/YYMMDD-xxx.md`

## 例外

- 用户明确说"不要用模板 / 就简单写个 readme / 不需要角色协作" → 按用户要求，不强制走技能
- 只是零散记个笔记、写个说明性小文档 → 不属于"复杂任务文档"，无需触发
