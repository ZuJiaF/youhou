# 临时文件命名规范

## 核心原则

**临时文件、临时云函数、临时目录等必须有明确的标识，便于识别和清理。**

## 命名规范

### 1. 临时云函数/云对象

命名格式：`{功能名}-linshi` 或 `{功能名}-temp`

示例：
- `initAiRules-linshi`
- `testPayment-temp`
- `migrateData-linshi`

要求：
- 文件夹名必须以 `-linshi` 或 `-temp` 结尾
- `package.json` 中的 `name` 字段也要包含后缀
- 创建时在代码注释中说明用途和预期删除时间

### 2. 临时脚本文件

命名格式：`{功能名}.temp.{ext}` 或 `temp-{功能名}.{ext}`

示例：
- `migrate.temp.js`
- `temp-fix-data.py`
- `test.temp.sql`

### 3. 临时目录

命名格式：`temp-{用途}/` 或 `临时/`

示例：
- `temp-uploads/`
- `temp-cache/`
- `临时/`

## AI 助手工作规范

### 1. 创建临时文件时

创建临时云函数/文件后，必须告知用户：

```
已创建临时云函数：initAiRules-linshi
用途：初始化 AI 规则数据
建议：运行成功后请删除该云函数（本地 + 云端）
```

### 2. 浏览代码时主动提醒

**重要：在浏览或搜索代码时，如果发现存在以 `-linshi`、`-temp`、`.temp.` 标识的文件/目录，应主动提醒用户是否还需要保留，建议清理。**

提醒格式：
```
⚠️ 发现临时文件：
- cloudfunctions/initAiRules-linshi/
- scripts/temp-fix.js

这些文件是否还需要？建议确认后清理。
```

### 3. 执行完成后确认

临时云函数运行成功后，必须询问：

```
临时云函数 {name} 已运行成功。
是否需要删除？
- 本地文件夹：{路径}
- 云端部署：需在控制台手动删除
```

## 清理检查清单

定期检查以下位置：
- [ ] 云函数/云对象目录中的 `-linshi`、`-temp` 后缀文件夹
- [ ] 项目根目录的 `临时/`、`temp-*/` 目录
- [ ] 脚本目录中的 `.temp.` 文件
- [ ] Git 未跟踪的临时文件

## 例外情况

以下情况可以不加临时标识：
- 框架/工具自动生成的临时文件（如 `.cache/`、`node_modules/`）
- 已在 `.gitignore` 中明确排除的目录
- 有明确业务含义的测试文件（如 `test/`、`__tests__/`）

## 项目特定扩展

不同项目可以在项目级 CLAUDE.md 中扩展：
- 定义项目特定的临时文件命名后缀
- 指定临时文件的存放位置
- 自动清理脚本的执行时机
