## 2.6.17 采集行为

用户确认另一对话停止后，已将之前准备的泰国站回归与共享解析合入主脚本。本地模拟测试通过，真实泰国响应及页面仍待验证。

- 泰国站只接收 `THB`（泰铢）；仍按当前商品编号匹配 `data.item`（详情商品节点）或 `data.item_details[]`（主商品优惠列表）。编号读取与马来站共用，支持四种商品编号字段，优惠列表校验 `shopid` / `shop_id`（两种店铺编号字段）。
- 读取 `price_min` / `price_max`（售价上下限）；缺失时要求完整有效的 `models[].price`（全部规格售价），再计算范围。
- 使用 100000 倍缩放产生候选金额；**泰国的实际金额单位仍待真实响应验证**。候选金额必须与主商品页面中的可见售价区间一致，才允许显示和发送。若倍率不符，保持未采集并记录候选及页面金额。
- 页面核对排除划线价、隐藏节点、运费说明和会员促销文案；不是直接从整页抽取第一笔金额。
- 若响应先到、页面尚未填价，保留候选，之后自动补读或手动刷新时再次核对。核对通过后保留完整规格范围，选择单个规格不覆盖区间。
- 预览携带 `฿` 标识，提交 `price_range`（每日价格区间字段）使用现有纯金额字符串格式，如 `69.00 - 312.00`。未核对候选不提交。
